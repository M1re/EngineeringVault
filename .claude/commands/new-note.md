Create a new knowledge-base note for the topic: **$ARGUMENTS**

Follow these steps:

1. Parse the section and topic from the input. The section must be one of:
   Programming, Computer Science, Data Persistence, Networks, Architecture,
   AI and ML, Security, Cloud, DevOps. If the section is ambiguous or missing,
   pick the best fit and say which you chose.
2. Create the file at `Vault/<Section>/<Topic Title>.md` (the Obsidian vault lives in `Vault/`;
   never write to `content/` — that folder is generated by Quartz Syncer).
3. Fill it out using the exact format in `Vault/Templates/Concept Note.md` and the writing rules in
   `CLAUDE.md`: mechanics + trade-offs + self-test questions, staff-engineer depth.
4. Frontmatter uses `status` and `publish` (not `draft`):
   - `status: creation` while it's being written; set `status: done` only when every section is
     genuinely complete (this is what fills the progress bar).
   - `publish: false` by default; set `publish: true` when it's ready to appear on the public site.
5. Write accurate content only. If any part is uncertain, mark it with a
   `> [!warning] Unverified` callout rather than guessing.
6. Add `## Related` wikilinks to existing notes where relevant.
7. Absolutely no personal or private data (this repo is public).

The note goes live on the site when the author publishes the vault via the Quartz Syncer
Publication Center — creating the file is enough on our side.

After writing, give me a one-paragraph summary of what you covered and which links you added.
