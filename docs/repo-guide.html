01 Общая картина

Твой репозиторий носит три «шляпы» одновременно. Это главное, что нужно уложить в голове — дальше всё встанет на места.

1 · ХРАНИЛИЩЕ

Obsidian-заметки

Папка content/ — это твои заметки в формате Markdown. Ты открываешь её в Obsidian и пишешь. Только это и есть «контент».

2 · САЙТ

Генератор Quartz

Quartz берёт заметки из content/ и собирает из них красивый сайт с поиском, графом и навигацией. Публикуется на GitHub Pages.

3 · ПОМОЩНИК

Автоматизация Claude

Папка .claude/ и CLAUDE.md — правила, команды, навыки и защита, чтобы Claude помогал писать заметки в едином стиле и не давал утечь личным данным.

Ключ ко всему

Весь репозиторий делится на два цвета: бирюзовое — контент и сайт (то, что видят люди), оранжевое — автоматизация (то, что помогает тебе писать). Я использую эти цвета по всему гайду.

02 Главная идея: content — это всё, остальное — механика

Самое частое, на чём спотыкаются новички: «зачем столько файлов вокруг?». Ответ простой:

Публикуется только content/. Всё остальное в корне — это «завод», который собирает сайт и помогает тебе писать. На сам сайт эти файлы не попадают.

Поэтому в Obsidian ты открываешь как vault именно content/, а не корень репозитория. Тогда тебе видны только заметки, а «завод» (Quartz, конфиги, .claude) не мешается под ногами.

Помни

Если открыть в Obsidian корень репозитория вместо content/ — Obsidian создаст лишнюю папку .obsidian в корне (такое уже случилось один раз, мы её удалили). Всегда открывай content/.

04 Папка content/ подробно

Здесь живёт всё, что станет сайтом. Три вещи, которые стоит понять:

Разделы и «обложки»

Каждый раздел — это папка (Programming/, Networks/ …). Внутри лежит файл index.md — он становится обложкой раздела на сайте. У него тег moc (Map of Content — карта содержимого).

Из чего состоит заметка

Открой Architecture/Idempotency.md — это эталон. Сверху идёт frontmatter (служебный блок между ---), потом тело по фиксированной структуре:

---
title: Idempotency        # заголовок
tags: [architecture]     # теги для графа и поиска
draft: false            # true = скрыто с сайта
---
# дальше тело: In one sentence → Why it matters →
# How it works → Trade-offs → Questions → Related → References

Эта структура заставляет раскрывать тему на уровне staff-инженера: не «определение из учебника», а механика + компромиссы + сложные вопросы.

Связи вместо папок

Заметки связываются вики-ссылками [[Название]]. Именно из них строится граф на сайте. Ссылка на ещё не написанную заметку — это нормально: она становится «маркером на будущее».

05 Четыре слоя автоматизации Claude

Это самая важная часть для понимания. У Claude четыре разных инструмента, и они отличаются тем, кто их запускает. Разложим:

Md
Запускается сам · читается каждую сессию

CLAUDE.md — «Конституция»

Файл с правилами базы: структура, стиль заметок, запрет личных данных, формат frontmatter. Claude автоматически подгружает его каждый раз, когда ты работаешь в этой папке. Это фон, который действует всегда.

/
Запускаешь ты · вручную командой

Слэш-команды .claude/commands/ — «Кнопки»

Готовые сценарии, которые ты вызываешь явно: /new-note, /expand, /review-note, /link. Каждый — это заранее написанный подробный промпт. Печатаешь команду — Claude выполняет сценарий.

✦
Включает сам Claude · когда уместно

Навык (skill) note-writer — «Мастерство»

Методология письма на staff-уровне. В отличие от команды, ты его не вызываешь — Claude сам подхватывает навык, когда видит, что ты пишешь или правишь заметку. Это «насмотренность», которая включается автоматически.

!
Запускает система · автоматически на событие

Хук check-secrets.js — «Охранник»

Скрипт, который срабатывает перед каждой записью файла. Сканирует текст на секреты и личные данные (ключи, токены, email) и блокирует запись, если что-то найдёт. Ты уже видел его в деле. Работает только внутри репозитория — публичную часть.

Как запомнить

CLAUDE.md = правила (всегда). /команды = ты нажал. Навык = Claude сам сообразил. Хук = система проверила. Разные триггеры — разные роли.

06 Движок Quartz

Quartz — это генератор статических сайтов: программа, которая превращает папку с Markdown в готовый HTML-сайт. «Статический» значит, что на выходе просто файлы — их дёшево и быстро отдавать, никакого сервера с базой не нужно.

ФайлЗа что отвечает
quartz.config.tsГлавные настройки: заголовок сайта, baseUrl (адрес публикации), тема, шрифты, что игнорировать. Тут мы прописали M1re.github.io/EngineeringVault.
quartz.layout.tsРаскладка страниц: где сайдбар, граф, оглавление, backlinks.
quartz/Сам код движка. Его не трогаем — он обновляется отдельно.
package.jsonСписок библиотек, от которых зависит Quartz. Ставятся командой npm install.

Локально посмотреть сайт до публикации: npx quartz build --serve → открыть http://localhost:8080.

07 Цепочка публикации: от заметки до сайта

Что происходит, когда ты хочешь опубликовать изменения. Каждый шаг — автоматический, кроме первых двух (их делаешь ты):

Ты · Obsidian
Пишешь заметку, ставишь draft: false
→
Ты · Obsidian Git
Commit-and-sync (кнопка / по таймеру)
→
GitHub
push в ветку main
→
GitHub Actions
deploy.yml запускается сам
→
Сборка
npm ci + quartz build → public/
→
GitHub Pages
Сайт обновлён 🎉

GitHub Actions — это робот-сборщик на серверах GitHub. Файл .github/workflows/deploy.yml — его инструкция: «на каждый push в main поставь Node, собери Quartz, выложи результат на Pages». Тебе не нужно ничего собирать вручную — достаточно запушить.

Обрати внимание

Между push и обновлением сайта проходит 1–2 минуты (робот собирает). Статус сборки виден во вкладке Actions на GitHub.

08 Черновики: что видно, а что нет

У каждой заметки в frontmatter есть поле draft. Это твой рубильник видимости:

draft: true

Заметка скрыта с сайта. Черновик, над которым ты ещё работаешь. Новые заметки Claude создаёт именно такими.

draft: false

Заметка публикуется. Ставишь, когда всё готово и проверено.

За это отвечает плагин Quartz RemoveDrafts — при сборке он просто выкидывает все черновики. Поэтому можно смело держать в репозитории недописанные заметки: на публичный сайт они не попадут, пока ты сам не переключишь флаг.

Золотое правило

Репозиторий публичный. Никаких личных данных, паролей, токенов, имён коллег, внутренних ссылок. Хук ловит очевидное, но финальная ответственность на тебе — используй /review-note перед публикацией.
