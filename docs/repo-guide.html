01 Общая картина

Твой репозиторий носит три «шляпы» одновременно. Это главное, что нужно уложить в голове — дальше всё встанет на места.

1 · ХРАНИЛИЩЕ

Vault (Obsidian)

Папка Vault/ — твои заметки в Markdown. Ты открываешь её в Obsidian и пишешь. Только тут живёт «контент».

2 · САЙТ

Quartz + Syncer

Плагин Quartz Syncer компилирует опубликованные заметки в content/, а Quartz собирает из них сайт с поиском, графом и навигацией на GitHub Pages.

3 · ПОМОЩНИК

Автоматизация Claude

Папка .claude/ и CLAUDE.md — правила, команды, навыки и защита, чтобы Claude помогал писать в едином стиле и не давал утечь личным данным.

Ключ ко всему

Весь репозиторий делится на два цвета: бирюзовое — контент и сайт (то, что видят люди), оранжевое — автоматизация (то, что помогает тебе писать). Эти цвета используются по всему гайду.

02 Vault пишешь ты, content генерит Syncer

Самое частое, на чём спотыкаются новички: две очень похожие папки. Запомни разницу — она главная:

Vault/

Открываешь в Obsidian и пишешь. Здесь живут все заметки, шаблоны, картинки и настройки Obsidian.

content/

Генерирует Quartz Syncer при публикации — руками не трогать. Это скомпилированная копия того, что ушло на сайт.

То есть как vault в Obsidian ты открываешь именно Vault/. Публикуется не «весь репозиторий» — только заметки с publish: true, и попадают они на сайт через Syncer, а не через обычный git-commit.

Не редактируй content/

content/ — собственность Syncer. Любая ручная правка там затрётся при следующей публикации. Пишешь всегда в Vault/.

04 Заметки, разделы и дашборды

Всё, что станет сайтом, живёт в Vault/. Три вещи, которые стоит понять:

9 разделов и folder-notes

Знания разложены на 9 разделов: Programming, Computer Science, Data Persistence, Networks, Architecture, AI and ML, Security, Cloud, DevOps. Каждый раздел (и каждый саб-топик внутри) — это папка с файлом index.md, который становится её folder-note: у него tags: [FolderNote], title, color, icon, publish: true и banner (обложка). Вложенность: раздел → саб-топик → заметка.

Из чего состоит заметка

Открой Architecture/Idempotency.md — это эталон. Сверху frontmatter (блок между ---), потом тело по фиксированной структуре:

---
title: Idempotency        # заголовок (его рисует сайт — H1 в теле НЕ пишем)
tags: [architecture]     # теги для графа и поиска
status: done            # creation = в работе, done = готово (прогресс-бар)
publish: true           # false = приватно, true = на сайт
---
# тело: In one sentence → Why it matters → How it works →
# Trade-offs → Questions → Related → References

Эта структура заставляет раскрывать тему на уровне staff-инженера: не «определение из учебника», а механика + компромиссы + сложные вопросы.

Живые дашборды и связи

Каждый index.md несёт блок datacorejsx — Datacore-дашборд: карточки саб-топиков с прогрессом + список заметок со статус-пилюлями. Он рекурсивный и одинаковый на всех уровнях. Заметки связываются вики-ссылками [[Название]] — из них строится граф; ссылка на ещё не написанную заметку это нормально, «маркер на будущее».

05 Четыре слоя автоматизации Claude

У Claude четыре разных инструмента, и они отличаются тем, кто их запускает. Разложим:

Md
Запускается сам · читается каждую сессию

CLAUDE.md — «Конституция»

Правила базы: структура, стиль заметок, запрет личных данных, формат frontmatter, публикация. Claude подгружает его автоматически каждый раз в этой папке — фон, который действует всегда. Рядом .claude/feedback.md — журнал твоих правок, тоже обязателен.

/
Запускаешь ты · вручную командой

Слэш-команды .claude/commands/ — «Кнопки»

Готовые сценарии-промпты: /new-note, /expand, /review-note, /link, а также /feedback, /consolidate-feedback и /update-guide. Печатаешь команду — Claude выполняет сценарий.

✦
Включает сам Claude · когда уместно

Навык note-writer — «Мастерство»

Методология письма на staff-уровне. Ты его не вызываешь — Claude сам подхватывает навык, когда видит, что ты пишешь или правишь заметку. «Насмотренность», которая включается автоматически.

!
Запускает система · автоматически на событие

Хуки .claude/hooks/ — «Охрана»

check-secrets.js срабатывает перед каждой записью файла: сканирует на секреты и личные данные (ключи, токены, email) и блокирует запись, если что-то найдёт (работает только внутри репозитория). check-ledger-size.js следит, чтобы CLAUDE.md и журнал правок не разрастались.

Как запомнить

CLAUDE.md = правила (всегда). /команды = ты нажал. Навык = Claude сам сообразил. Хук = система проверила. Разные триггеры — разные роли.

06 Движок: Quartz + Quartz Syncer

Quartz — генератор статических сайтов: превращает Markdown в готовый HTML (никакого сервера с базой). Quartz Syncer — плагин Obsidian, мост между твоим vault и сайтом: он прекомпилирует Datacore/Dataview-дашборды в статический HTML и пушит результат в content/. Только он трогает content/.

ФайлЗа что отвечает
quartz.config.tsГлавные настройки: заголовок, baseUrl (M1re.github.io/EngineeringVault), тема (Notion-палитра + шрифт Inter), что игнорировать.
quartz.layout.tsРаскладка страниц: сайдбар, граф, оглавление, порядок разделов (Programming→DevOps), обложка над заголовком.
quartz/components/Banner.tsxНаш компонент: рисует обложку (banner) поверх folder-notes. Читает то же поле, что и плагин Banners в Obsidian.
quartz/Код движка. Его не трогаем — обновляется отдельно.

Локально посмотреть сайт до публикации: npx quartz build --serve → открыть http://localhost:8080.

07 Цепочка публикации: от заметки до сайта

Что происходит при публикации. Первые два шага делаешь ты, дальше — автоматика:

Ты · Obsidian
Пишешь заметку, ставишь publish: true
→
Ты · Quartz Syncer
Publication Center → Publish
→
GitHub
Syncer пушит content/ в main
→
GitHub Actions
deploy.yml запускается сам
→
Сборка
quartz build → public/
→
GitHub Pages
Сайт обновлён 🎉

GitHub Actions — робот-сборщик на серверах GitHub. Файл .github/workflows/deploy.yml — его инструкция: «на каждый push в main поставь Node, собери Quartz, выложи на Pages». Тебе не нужно собирать вручную — Syncer пушит, робот собирает.

Авто-публикация выключена

Раньше был watcher (scripts/watch-publish.mjs), публиковавший сам на каждое изменение. Он отключён — конфликтовал с ручными правками и заклинивал Syncer. Рубильник: файл scripts/.autopublish-disabled (удалить → снова включится). Пока публикуем руками. Отслеживается в issue #1.

08 status и publish: что готово, что видно

У заметки два независимых поля-рубильника во frontmatter:

publish: false

Заметка приватна — остаётся только в Vault/. Новые заметки Claude создаёт именно такими.

publish: true

Заметка идёт на сайт. Syncer публикует только такие.

status: creation

Заметка в работе — не заполняет прогресс-бар на дашбордах.

status: done

Заметка готова — заполняет прогресс-бар раздела.

Важно для сайта

Чтобы нестандартные поля (banner, color, status, icon) доехали до сайта, в настройках Quartz Syncer должно быть включено «Include all properties».

09 Тема и обложки (Notion-стиль)

Вид базы сделан «под Notion» и одинаков в Obsidian и на сайте — это железное правило. Тема зеркалится в двух местах от одних и тех же данных:

ЧтоНа сайте (Quartz)В Obsidian
Палитра + шрифт Interquartz.config.tsсниппет .obsidian/snippets/notion.css
Обложка (banner)components/Banner.tsxплагин Banners

Обложки (banner) есть только у топиков и саб-топиков (folder-notes), по умолчанию attachments/banners/aurora.svg. Поставить свою картинку или гифку — командой Set Cover (Templater): выбираешь файл из attachments или вставляешь URL. Перед публикацией на сайт: node scripts/sync-banners.mjs (копирует картинку в content/). Подробно — в docs/covers.md.

Золотое правило

Репозиторий публичный. Никаких личных данных, паролей, токенов, имён коллег, внутренних ссылок. Хук ловит очевидное, но финальная ответственность на тебе — используй /review-note перед публикацией.
