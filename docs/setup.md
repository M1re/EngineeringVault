# Setup & Workflow

How to work on this vault locally. (Documentation — not published to the site.)

## 1. Open the vault in Obsidian

Open the **`Vault/`** folder as your Obsidian vault (`Open folder as vault` → select
`.../EngineeringVault/Vault`). Your notes live here.

The repo root holds the site generator (Quartz) and automation (`.claude/`). The `content/` folder
is **generated by Quartz Syncer** — don't open or edit it.

## 2. Obsidian community plugins

Install from **Settings → Community plugins → Browse**. The ones this setup relies on:

| Plugin | Why |
| --- | --- |
| **Datacore** | Runs the home + section dashboards (dynamic progress cards). Required. |
| **Quartz Syncer** | Publishes the vault to the site, precompiling Datacore/Dataview to static HTML. Required. |
| **Folder Notes** | Lets a section's `index.md` act as the folder's note (icon, color, dashboard). |
| **Homepage** | Opens `index` on startup. |
| **Obsidian Git** | Backs up the whole repo to GitHub (separate from publishing). |
| **Banners** | Renders the Notion-style cover image/GIF on topics & sub-topics (the `banner` field). |
| **Excalidraw**, **Advanced Tables**, **Linter**, **Templater** | Diagrams, tables, formatting, templates. |

Also enable the **`notion`** CSS snippet (**Settings → Appearance → CSS snippets**) — it applies the
Notion-inspired palette + Inter font so the vault matches the site.

## 3. Creating topics, sub-topics, and notes

Everything is scaffolded by three **Templater commands** (Command palette → *Templater: Open insert
template modal*, or bind hotkeys). Hierarchy: **Topic → Sub-topic → Note**; notes live only inside a
sub-topic.

| Command | Makes | Asks for |
| --- | --- | --- |
| **New Topic** | a section (Programming, Security…) + a card on the home page | title, folder, description, colour, icon |
| **New Sub-topic** | a sub-topic under a topic (C#, .NET…) | parent topic, title, folder, colour, icon |
| **New Note** | a concept note inside a sub-topic | sub-topic, title, tags (thematic; existing + new) |

Each folder-note gets a `banner` cover (default aurora) — change it per note with **Set Cover** (see
[covers.md](covers.md)). Frontmatter uses **`status`** (`creation` → `done`, fills the progress bar)
and **`publish`** (`false` → `true` when ready for the site).

> [!warning] Don't pick "Concept Note" / "Folder Note" in the template list
> Those are internal skeletons (they now refuse to insert into a note). Always use the **New …**
> commands — they create files in the right place instead of pasting into the current note.

## 4. Working with Claude Code

Run `claude` from the repo root. Custom commands:

| Command | What it does |
| --- | --- |
| `/new-note Networks — DNS` | Creates a fully-formatted note in the section. |
| `/expand DNS` | Deepens an existing note to the staff-engineer bar. |
| `/review-note DNS` | Checks privacy, format, and depth before publishing. |
| `/link DNS` | Weaves a note into the graph with wikilinks. |

Claude auto-loads `CLAUDE.md`, the `note-writer` skill, and the binding feedback ledger
(`.claude/feedback.md`). A pre-write hook blocks accidental secrets/personal data.

## 5. Publishing

Notes go live through **Quartz Syncer**, not a git commit:

1. Set `publish: true` (and `status: done` when complete).
2. Open the **Publication Center** (ribbon icon or Command palette → *Quartz Syncer: Open
   Publication Center*).
3. Click **Publish**. Syncer compiles the published notes (precompiling Datacore to static HTML),
   pushes the result to `content/` on `main`, and GitHub Actions rebuilds the site.

Live site: https://m1re.github.io/EngineeringVault/

> [!tip] Covers / banners
> To keep the `banner` field (and `color`/`status`/`icon`) in published notes, turn **ON**
> Quartz Syncer → **"Include all properties"**. See [covers.md](covers.md) for the full
> cover / GIF workflow.

### Auto-publish (currently disabled)

There is a watcher (`scripts/watch-publish.mjs`) that used to publish automatically on every
`publish: true` change. It's **disabled** — it raced with manual edits and wedged Syncer. The
kill-switch is the file `scripts/.autopublish-disabled`; while it exists the watcher exits on
launch. Publishing is manual (the Publication Center above, or the CLI). Tracked in
[issue #1](https://github.com/M1re/EngineeringVault/issues/1); **re-enable by deleting that file**.

> [!note] One rule above all
> Anything we build must look the same in Obsidian **and** on the deployed site. Prefer Datacore
> (precompiled by Quartz Syncer) or plain Markdown/HTML — never a feature that only works in one.
