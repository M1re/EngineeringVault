# Engineering Vault — Agent Operating Guide

The one instruction file for every agent here (Claude Code, OpenCode, Codex); `CLAUDE.md` imports it.
This **public** Obsidian vault is the author's study guide: what a **senior / tech lead** engineer
should understand deeply, from the basics to advanced, ready for interviews. Notes live in `Vault/`
and are published with **Quartz** (via **Quartz Syncer**) on GitHub Pages.

## 🚨 Non-negotiable rules

1. **This repo is PUBLIC. Never write personal or private information.** No real names, emails,
   employers, colleagues, internal project names, private URLs, tokens, API keys, passwords,
   or anything identifying the author or their company. If a source has such data, strip it.
2. **Never invent facts.** Technical accuracy matters more than volume. If unsure, say so in the
   note (a `> [!warning] Unverified` callout) or leave it out. Prefer primary sources.
3. **Language:** note body and `summary` in **Russian**; technical terms, `title`, headings, and code
   in **English**. An English translation is planned (issue #22).

## Feedback ledger (binding)

`.claude/feedback.md` holds the author's feedback. Duties:

1. **Obey the "Active rules"** before writing or editing anything; the "Archive" is history only.
2. **Record feedback proactively.** When the author voices a correction, dislike, or preference —
   anywhere, unprompted — capture it that turn: refine an active rule (preferred) or add one, and
   log it in the Archive.
3. **Keep it lean.** Mature rules move into structure (skill, template, hook, Linter) and leave the
   ledger. When the size tripwire (`.claude/hooks/check-ledger-size.js`) nudges you, consolidate.

## Repository layout

- `Vault/` — the Obsidian vault, ALL notes: `index.md` (home dashboard), `<Section>/index.md`
  (section folder-notes), `Templates/` (unpublished), `attachments/` (images, binaries).
- `content/` — GENERATED by Quartz Syncer, never edit. `.claude/` — skills, reviewer, commands, hooks.
- Site: Quartz v5. `quartz.config.yaml` (settings, plugins, layout), `quartz.ts` + `custom/` (our
  code: cover banner, explorer order, summary→description), `quartz/styles/custom.scss` (theme).
  Do not edit other engine files under `quartz/`; community plugins install into `.quartz/`
  from `quartz.lock.json`.
- Every note sits in exactly one of 9 sections: Programming, Computer Science, Data Persistence,
  Networks, Architecture, AI and ML, Security, Cloud, DevOps.

## Note format

Every concept note follows `Vault/Templates/Concept Note.md`. Frontmatter:

```yaml
---
title: "Human Readable Title"
summary: "One plain line"     # required once done; feeds the site description and link previews
tags: [thematic-kebab-tags]   # concepts the note touches, NOT the folder path
status: new        # new = nothing written yet | in-progress = being written | done = written & validated
publish: false     # false = stays private; set to true to publish to the site
created: YYYY-MM-DD
---
```

Required body sections, in order (do **not** add a top-level `# Title` heading — Quartz renders the
frontmatter `title` as the page heading):
- `> [!summary]` — the gist in 1–3 plain sentences (+ one line on why it matters)
- topic sections with short noun-phrase headers, from the basics to advanced (no "How it works")
- `## Pitfalls & Trade-offs` — real failure modes and "X buys A at the cost of B"
- `## In Production` — real domain code from a real system, bad version and fix, never foo/bar
- `## Questions` — interview cards `> [!qard]- <q>`, a senior's answer folded inside (Qard flashcards)
- `## Related` — wikilinks; `## References` — primary sources

`npm run validate` (`scripts/validate-vault.mjs`, also in CI) checks frontmatter, `summary` on `done`
notes, section order, no body `# Title`, code-fence languages, References, and folder-note fields.

## Where the detailed rules live (loaded on demand)

- Writing a note → the **note-writer** skill (`.claude/skills/note-writer/`): hub + sub-notes, section
  pattern, writing standard, verification protocol.
- Reviewing a note → the **reviewer** subagent (`.claude/agents/reviewer.md`; without subagents, run
  that prompt in a fresh session). Covers → `docs/covers.md`; new notes → the **New …** commands.

## Reviewer gate (enforced)

After creating or changing a concept note (`Vault/**.md`, except `index.md` and `Templates/`):

1. Run the reviewer on the note's current text — a fresh context that did not write it.
2. Apply every must-fix.
3. Record it: `node .claude/hooks/review-receipt.js --verdict PUBLISH-READY|FIXES-APPLIED "<note>"`.

The receipt is bound to the note's content hash (minus `status:`/`publish:`), so any later edit voids
it; a Stop hook refuses to end the turn without a fresh one. Never record a receipt without a
reviewer pass in this session. Agents set `done` only on a note with a fresh receipt.

## Linking conventions

- Link liberally with `[[wikilinks]]`. A link to a note that doesn't exist yet is fine — it's a
  roadmap marker. Use folder-qualified links when titles could collide: `[[Networks/index|Networks]]`.
- Every new note should link to at least one existing note and be linked from its section `index.md`.
- Section landing pages are always `<Section>/index.md` — folder-notes with `tags: [FolderNote]`,
  an `icon` (lucide name), a `color` (hex), and `publish: true`.
- **Nesting:** Section → sub-topic → note. Every folder is a folder-note from
  `Vault/Templates/Folder Note.md` (`index.md`, `tags: [FolderNote]`, `title`, `publish: true`,
  `banner` — default `attachments/banners/aurora.svg`) with the recursive dashboard. Folder names are
  URL-safe (`CSharp`) with a pretty `title` (`C#`): no `#`, spaces, or leading dot. Covers belong to
  folder-notes only.

## Publishing (Quartz Syncer)

- **Commit = publish.** The pre-commit hook (`scripts/sync-quartz.mjs`) exports the vault through
  the Obsidian CLI (Syncer local mode, Datacore precompiled to HTML) and stages `content/`; pushing
  `main` deploys Pages. Never edit `content/`. Shared Syncer settings:
  `scripts/quartz-syncer.defaults.json`; its `data.json` is per-machine. New machine: the README.
- Only notes with `publish: true` reach the site; everything else stays private in `Vault/`.
- The progress bar shows all three statuses (% = `done` share); mobile publishes run
  `scripts/regen-dashboards.mjs`. Syncer's `includeAllFrontmatter` stays ON so `banner`/`status` survive.
- **Anything we build must render the same in Obsidian AND on the deployed site** — use tech that
  works in both (Datacore + Quartz Syncer, or plain Markdown/HTML).
- Look & feel: Notion-inspired theme in both surfaces (`custom.scss` / `notion.css` + **Banners**);
  folder-note covers via **Set Cover**, mirrored by the commit hook. See `docs/covers.md`.
